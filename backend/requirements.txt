# hop-core — consumed as a versioned artifact, never by filesystem path. A path like
# `-e ../hop-core` only resolves on one machine and breaks the Docker build, because the
# compose build context is ./backend and ../hop-core sits outside it. The [dita] extra
# pulls lxml for hop_core.dita.
#
# To move to a new hop-core, bump the tag below and rebuild the venv (pip will not swap a
# git URL in place on an existing install).
#
# SINGLE SOURCE OF TRUTH POLICY:
# hop-core owns the versions of its own dependencies — auth, crypto, oauth, rate-limiting,
# lxml, pydantic-settings, email-validator, python-multipart, itsdangerous. Those are NOT
# re-pinned here; they resolve transitively from hop-core so there is exactly one version
# constraint for each and no drift/conflict. Only packages this app imports directly are
# listed below. CI runs `pip check` to catch any incompatibility.
